# Synthèse CONTEXTE du projet

Voici la synthèse du contexte du projet, basée sur nos échanges et sur le fonctionnement de la solution développée :

### 1. Objectif général

Le projet vise à concevoir un **outil Web autonome (HTML/JS)** permettant de consolider, visualiser et exporter les données d'homologation issues des API CompareCycle. Il permet de contrôler l'état des transactions et des litiges pour une liste donnée de points de vente (PDV / `code_pos`).

---

### 2. Architecture & Fonctionnalités Clés

* **Interface de Configuration Dynamique :**
* Saisie de l'**URL de l'API** et du jeton **AUTOLOGIN** (permettant d'adapter l'outil à différents environnements ou partenaires).
* Sélection d'une **Date de début (`date_from`)** au format `YYYY-MM-DD` pour filtrer les données à partir d'une période précise et éviter de charger l'historique complet.
* Zone de saisie pour intégrer la liste des points de vente (**PDV / code_pos**).


* **Interrogation des APIs & Filtrage :**
* Traitement séquentiel de chaque `code_pos` sur l'endpoint principal (`/Homologation`).
* Gestion native des réponses multi-transactions (1 résultat API peut contenir plusieurs objets de transaction).
* Filtrage automatique pour n'afficher dans le tableau que les réponses contenant des transactions réelles (exclusion des réponses vides).


* **Restitution sous forme de Tableau HTML :**
* Structure des données mappée sur les champs JSON renvoyés par l'API :
* **Transaction :** `label_product` (n° transaction), `pandas_session_id` (n° session).
* **États / Conditions :** Grades et combinaisons initiaux et finaux (`conditions`).
* **Litiges :** Concaténation formatée des codes et libellés de litiges (`code - label_fr`).
* **Produit :** Marque, modèle, nom du produit, IMEI (`product`).
* **Dates :** Création, réception, homologation, dispatch (`dates`).




* **Gestion des Preuves Photos (Modale) :**
* Exploitation du champ `has_proofs`.
* Si `has_proofs` est vrai (`Oui`), la cellule affiche un bouton cliquable qui interroge l'endpoint dédié (`/Homologation/proofs`) en fournissant le `code_pos` et le `label_product`.
* Affichage des preuves sous forme de vignettes d'images (Base64) dans une fenêtre modale.


* **Exportation des données :**
* Bouton d'**export CSV** permettant de télécharger l'intégralité du tableau généré avec séparateur `;` et encodage UTF-8 (compatibilité Excel avec caractères accentués).



---

### 3. État Actuel du Code

Le code HTML/JavaScript a été entièrement **expurgé** de toutes les données de test (URL spécifiques, clés autologin ou identifiants de points de vente réels). Il est livré sous la forme d'un composant générique et réutilisable prêt à être déployé ou partagé en toute sécurité.
